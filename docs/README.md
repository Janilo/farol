# docs

Documentos de método e decisão do Farol. **A fonte de verdade é aqui**: edite estes arquivos, não uma cópia. Eles vieram da pasta de trabalho privada do Janilo, e o repo passou a ser o original em 28/jul/2026.

| Arquivo | O que é |
|---|---|
| [`DESIGN.md`](DESIGN.md) | Spec do design system derivado. Começa pela tabela das **onze decisões travadas**, que não se reabrem sem fato novo. Os valores de cor têm contraste WCAG medido. |
| [`DESIGN-conteudo-telas.md`](DESIGN-conteudo-telas.md) | Conteúdo e escopo das telas: os quatro eixos da rubrica com pesos, os 19 gatilhos, quota da demo, dados exatos do exemplo canônico. |
| [`COPY.md`](COPY.md) | Copy aprovada, slot por slot, com o registro de quais decisões estão fechadas. |
| [`ROADMAP.md`](ROADMAP.md) | Estado das fases: o que está fechado, o que falta e o que saiu do escopo por fato sobre as fontes. |

A linguagem ubíqua vive na raiz, em [`../GLOSSARIO.md`](../GLOSSARIO.md), porque governa o código e não só o design.

## Por que os pesos da rubrica estão num repo público

A rubrica de priorização é método de consultoria, e ela está aqui de propósito: a página `/metodologia` do produto explica os quatro eixos ao visitante, porque mostrar o cálculo **é** o argumento do Farol. Um score sem a conta na frente é um número que pede fé.

O que não está aqui: os doze cases reais que calibraram a rubrica, o ICP detalhado e a base de clientes. Esses seguem privados.
